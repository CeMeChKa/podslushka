# Школьная подслушка — Telegram-бот

Python 3.10+, `pyTelegramBotAPI` (telebot) и SQLite. Бот принимает текстовые заявки на публикацию, перед публикацией отправляет их администраторам для проверки; также позволяет написать администраторам личное сообщение и показывает кнопки-ссылки параллелей. Главный администратор может добавлять, переименовывать, менять ссылки и удалять параллели без перезапуска.

## Запуск локально

1. Установите Python 3.10+ и зависимости: `python -m pip install -r requirements.txt`.
2. Скопируйте `.env.example` в `.env` и задайте значения. Сам бот читает переменные окружения, поэтому экспортируйте их перед запуском (либо используйте `export $(grep -v '^#' .env | xargs)` в Linux/macOS). Не публикуйте токен.
3. Добавьте бота администратором канала с правом публикации сообщений.
4. Запустите: `python bot.py`.

## Развёртывание на VPS через Docker Compose

Нужен VPS с Ubuntu 22.04/24.04 и SSH-доступом. Команды ниже выполняются на сервере от пользователя с `sudo`.

1. Установите Docker Engine и Compose plugin по официальной инструкции Docker для Ubuntu: https://docs.docker.com/engine/install/ubuntu/ (включая настройку репозитория Docker и установку пакетов `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`). Проверьте: `sudo docker compose version`.
2. Загрузите репозиторий на сервер (подставьте URL репозитория): `git clone <URL_репозитория> podslushka && cd podslushka`. Либо передайте файлы проекта на VPS другим способом.
3. Создайте конфигурацию: `cp .env.example .env && nano .env`. Заполните `BOT_TOKEN`, `OWNER_ID`, `ADMIN_IDS` и `CHANNEL_ID`. Добавьте бота администратором канала с правом публикации. Файл `.env` содержит секрет и не должен публиковаться.
4. Соберите и запустите в фоне: `sudo docker compose up -d --build`.
5. Убедитесь, что контейнер работает: `sudo docker compose ps`; журнал: `sudo docker compose logs -f bot` (выход из просмотра — Ctrl+C, контейнер продолжит работу).

Обновление после изменения кода: `git pull && sudo docker compose up -d --build`. Остановка: `sudo docker compose down`. Данные SQLite хранятся в отдельном Docker volume и переживают пересоздание контейнера. Посмотреть его имя: `sudo docker volume ls`; для резервной копии базы остановите контейнер или сделайте копию volume. Не используйте `docker compose down -v`, если хотите сохранить базу.

`OWNER_ID` — единственный главный администратор, управляющий параллелями. `ADMIN_IDS` — ID проверяющих, включая главного автоматически. `CHANNEL_ID` — `@username` канала или числовой ID. База `podslushka.sqlite3` создаётся автоматически в текущей папке.

## Сценарии

- **Предложить публикацию**: принимается текст, создаётся заявка и рассылается проверяющим. В личном сообщении администратора доступны кнопки публикации/отклонения. Уведомление о результате приходит автору.
- **Написать админу**: сообщение доставляется только администраторам, с ID отправителя для ответа вручную.
- **Параллели**: отображаются сохранённые Telegram-ссылки.
- **Управление параллелями**: главный администратор добавляет новую пару «название + ссылка», редактирует или удаляет запись.

Команды: `/start`, `/help`, `/cancel`, `/id`. Проверку администратора бот выполняет на стороне сервера по Telegram ID. Для публикаций поддерживается текст (до 3500 символов); вложения не пересылаются.
